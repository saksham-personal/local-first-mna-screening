# Phase 3 plan — LLM Suite instruction sets, Search Space, grid v3, polish

Source: the analyst's Checkpoint 2 review (2026-10-08). Decisions: Arctic-embed-m-v2 **ONNX int8** for local testing; **Meilisearch** for lexical Search Space; real MID data will NOT be uploaded — the analyst exports the repo and wires the real LLM Suite / providers / MID later, so everything provider-facing ships as a clean **stub** with pristine prompts.

## A. LLM Suite as the controller ("instruction sets")

LLM Suite (context ≈200–250k tokens) is poor at JSON tool calls and good at Markdown. So the controller never asks for "tool calls". It asks for a short **Context** section, a **Reasoning** section and an **Instruction set** in a fixed, human-readable Markdown shape. A tolerant deterministic parser turns the instruction set into validated tool calls (a classifier may replace it later; parsed/raw pairs are logged as training data).

- **Conversation ids.** A new LLM Suite chat/context = a new `conversation_id`; continuing = reuse it. One id per screening session; "New context" rotates it. The controller tracks approximate tokens per conversation and rotates with a compact hand-off summary before ~180k tokens.
- **Prompt master.** `prompts/*.md` stays the single source (Rust + Node loaders already read it). Header gains **Context**: `ID · Description · What it does · Context (when/where it is sent, conversation) · Inputs · Output · Version`, then `===@@=== STARTING ===@@===` … `===@@=== END ===@@===`. Prompts are rewritten short (target: system prompt + tool guide ≤ 2.5k tokens). `prompts/INDEX.md` lists every prompt, where it is used, and its token estimate (generated by a script; a test fails if a prompt is not listed or exceeds its budget).
- **Output shape (in the prompt, never called "tool calls"):**
  ```
  ## Context
  <1–3 sentences: what I understood>
  ## Reasoning
  <short visible reasoning>
  ## Instruction set
  1. **search_mid** — Find claims software vendors
     - rationale: Broad claims/policy software group
     - keywords: claims software; policy administration; insurer*
     - expression: (k1 OR k2) AND k3
  2. **score_mid_semantic**
  ## Notes for the analyst (optional)
  ```
- **Parser (Rust `instruction_set.rs`)**: accepts heading variants (`#`–`###`, bold headings, "Instructions", "Steps", "Actions", "Plan"), numbered or bulleted items, `**name**`/`` `name` ``/plain names, fuzzy action matching (case, spaces, hyphens, plurals, a synonym table), `key: value` / `key = value` / `**key**: value`, multiline values, lists as `;`/`,`/sub-bullets, booleans/numbers/"none", stray code fences, JSON accidentally emitted (parsed as a fallback), tables, prose before/after, duplicated keys (last wins + warning), missing sections (whole reply scanned). Output: `{context, reasoning, notes, instructions:[{index, action, args, warnings, raw}], rejected:[{raw, reason}]}`. Each instruction is validated against the tool schema and policy (approval gates unchanged); failures go back to LLM Suite as short "Instruction feedback" on the same conversation (max 2 repairs).
- **UI**: assistant messages from LLM Suite render Context + Reasoning (collapsible) + the instruction set as a checklist with live status per instruction (queued/running/done/failed + result summary).
- **Stub**: `mna-ui/server/llmsuite-stub.mjs` (opt-in) — `POST /v1/conversations/{id}/messages {model, message}` → `{conversation_id, reply_markdown, usage}` with deterministic replies (instruction sets for common intents, malformed variants for parser tests). The real adapter is one module the analyst replaces.

## B. Data, grid and exports

- **MID import = all columns.** `mid-index.json` becomes: `columns` (every workbook column is imported and stored), `search_columns` (FTS), `description_columns` (LLM/semantic text), `identifier_columns`, `display` (default visible grid columns). **No weights** (bm25 uniform); the Build Index "Columns used" section is removed. Editing the JSON and re-importing (Build Index) applies it.
- **ISCC ↔ MID mapping** in `mna-tools/config/source-mapping.json` (the analyst's table: CID→Crescendo ID, ECI→ECID, Company Name→Company, Company Website→Website, City→HQ City, State→HQ State, LOB→BU Level 05 … Sub×5 LOB→BU Level 11, iQ Link dropped; all other ISCC columns become `ISCC_<name>`, unmapped MID columns `MID_<name>`). Views: **MID tab** = MID columns, no prefixes; **ISCC tab** = ISCC columns, no prefixes; **All** = merged columns (prefixes only where both exist); if only MID ran, All looks exactly like MID plus `ISCC_Score` "—"; if only ISCC ran, All looks like ISCC plus `MID_Keyword Score`/`MID_Semantic Score` "—".
- **Scores**: drop "MID keyword match %" as a column; **MID Score** keeps the keyword tooltip and gets a score distribution. **Coverage** = banker fields (Banker Name, IB Client Executive, CB/GCB Banker, Quality of connection, R12 call counts, Last Call Date). **Hydration** column group/tab = PB · ROGO · Bing (moved out of Coverage).
- **Grid v3 performance**: a per-run denormalized grid table maintained on write (discovery, imports, reviews, rounds) so a page is one indexed read; Companies tab shows page 1 immediately (AG Grid pagination, 100/250/500 per page) while the rest streams; text-heavy fields (descriptions) load per visible page; no 2 MB failures (bounded pages + continuation).
- **Exports**: background export jobs that stream rows to XLSX (constant-memory writer) with progress in Activity and a download link; never block the UI.
- **Screening setup**: preparation only counts companies; the input file is built as an Activity step when the run starts. Description sent = MID + ISCC concatenated when both exist; LinkedIn URL only offered after PB hydration; **Model** dropdown (stub list), no "Automatic"; batch size slider + box, M365 default 10, warning above 20.
- **Bing research**: no per-company preview/save; query rows generated on the fly in batches when sending (fixes the "Saving…" stall).

## D. Search Space (sidebar, under New screening)

- **MID mode**: paged table of the whole active MID bundle (100 rows/page); keyword chips + Query Expression bar (AND / OR / NOT / parentheses buttons, Recent searches, Apply) like the reference; **Lexical** (Meilisearch; keywords alone = OR across search columns; a query expression overrides) or **Semantic** (free text → Arctic embeddings, cosine ranking); exports; add selected companies to a screening.
- **ISCC mode**: query text + result count → ISCC (stub/simulated) → Excel dump → hydrate → table.
- Meilisearch runs as a managed local process (binary on E:), synced after each Build Index activation.
