# Architecture critique and correction status

The proposal correctly separates model interpretation from deterministic execution. The corrected implementation uses one authoritative domain store and broad core-business discovery. This table records the final decisions and their implementation status. It supersedes the earlier critique's statements that the v2 execution contract did not exist.

| Proposed choice | Required correction | Current status |
|---|---|---|
| Filter geography, revenue, size, ownership and industry codes before retrieval | Search core-business text in MID and live ISCC. Preserve other conditions for deferred analyst review. Only approved core-business exclusions can narrow discovery. | **Implemented.** Non-core structured filters are ignored and reported. Query negation cannot bypass exclusion approval. Free-text criteria interpretation remains an orchestrator responsibility. |
| Assume 100% Recall@50 and stop at 50 | Use up to **1,000 results per query** now. Do not infer population recall from a model benchmark. | **Implemented.** MID and ISCC default/max limits are 1,000. A representative recall benchmark is still planned. |
| Rerank a tiny group and discard everything else | Rerank the first **500 per source/query**, retain the remaining retrieved companies, and preserve separate source scores. | **Implemented adapter.** Validates a complete rerank response and retains the tail. Reranker model selection and real inference are **planned**. |
| Treat a vector without model metadata as interchangeable | Use Arctic M v2 INT8 ONNX, **768 dimensions**, with replaceable adapters and model/version/text-hash index identity. | **Implemented interfaces, index and CPU worker.** Actual ONNX assets and corpus inference are **unverified**. A model or preprocessing change requires a new version and rebuild. |
| Use Needle3 to compile model actions | Give LLMSuite a small natural-language tool catalog and require typed text blocks. Validate in Rust; request at most two repairs. | **Implemented.** No Needle3 dependency. Malformed commands do not execute. |
| Use an unrestricted local model broker | Local inference is embedding/reranking only. LLMSuite owns orchestration and logical subagents; every LLMSuite message shares the **7 per rolling minute** gate. M365 is an optional separate analysis/question path. | **Implemented durable gate and execution adapter.** Production orchestration wiring and corporate deployment validation are **planned/unverified**. |
| Require LinkedIn for every Copilot call | LinkedIn is optional. If genuine PB company LinkedIn is hydrated, include it in M365 inputs. | **Implemented.** General questions work without company context. Prepared M365 plans cannot omit available PB LinkedIn. |
| Use graph checkpoints as the domain database or scheduler | SQLite owns domain truth, approvals, jobs, outbox, leases, request audit and immutable results. Parquet keeps wide source data. LangGraph keeps the workflow cursor. | **Implemented in Rust.** The offline LangGraph scaffold is tested; a durable production saver and live ports are **planned**. |
| Use one confidence/score for all purposes | Keep retrieval source/query scores, prompt/batch model assessments, and claim confidence/provenance separate. Research leads remain UNKNOWN until verified. | **Implemented.** Analyst-only verification is separate from saving evidence or receiving a model response. |
| Supply one canonical row to all models | Build a run-scoped projection: PB name and website independently preferred; labeled PB+MID+ISCC descriptions; coverage and selected row hashes. | **Implemented.** Full selected scope is retained. A 64 MB snapshot cap fails explicitly; streaming preparation above that cap is **planned**. |
| Trust model-returned company IDs | Freeze a server-side global `index -> pk` map for each job. Require exactly index plus requested columns. Strictly parse and join or quarantine the entire response. | **Implemented.** Missing/duplicate/foreign indexes, malformed tables and invalid scores are rejected. Historical PKs survive identity promotion. |
| Approve only a profile version or action graph | Version the full prepared-plan contract and approval digest, including the compiled prompt, selected source data, deployment, batching and all execution options. Rehydrate and reapprove after relevant edits/uploads. | **Implemented schema v2.** Preview shows the complete execution prompt. Dispatch rechecks freshness; late responses remain historical and ineligible after a source change. |
| Retry any timeout automatically | Record send attempts, consume capacity at dispatch, quarantine ambiguous sends and explicitly reconcile the matching attempt. | **Implemented.** No automatic retry of a request that might have reached the provider. Late responses can be retained against their original lease token. |
| Describe external integrations as already running | Label paths as implemented, configured_but_unverified or planned. Show `executed:false` on prepared handoffs. | **Implemented status/approval contract.** The UI saves prepared jobs; configured background adapters dispatch only after approval. Direct questions and draft generation use configured provider adapters with the shared gate. Corporate connections remain unverified; disconnected paths execute nothing. No result is fabricated. |

These corrections are implemented at the deterministic service boundary. They do not claim that a corporate API, browser/CDP ISCC pull, embedding asset, or reranker has been connected. See [the architecture](BACKEND_ARCHITECTURE.md), [execution contract](EXECUTION_CONTRACT.md), [retrieval setup](RETRIEVAL.md) and [validation record](../IMPLEMENTATION.md).

Snowflake's [official Arctic M v2 model card](https://huggingface.co/Snowflake/snowflake-arctic-embed-m-v2.0) documents 768-dimensional output, query-prefix handling, CLS pooling and normalization. Its benchmark scores do not establish recall on this application's MID/ISCC population. LangGraph's [persistence](https://docs.langchain.com/oss/python/langgraph/persistence) and [interrupt](https://docs.langchain.com/oss/python/langgraph/interrupts) documentation describe checkpoints and resume semantics; an interrupted node restarts, so domain effects must remain idempotent and independently durable.
